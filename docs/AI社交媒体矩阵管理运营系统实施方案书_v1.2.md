## 一、项目概述

### 1.1 项目目标

通过一套**全免费、本地部署、AI驱动**的工具组合，实现"1人运营10个国内社交媒体账号"的矩阵化管理，验证以下核心假设：

1. AI能否将内容生产效率提升3倍以上（从采集到发布的全链路）
2. 浏览器自动化发布能否稳定运行，封号率是否可控
3. 10个号的矩阵规模能否在单人维护下持续产出
4. AI工具教程类内容在多平台分发后的流量表现差异

### 1.2 项目范围

| 维度 | 范围内 | 范围外 |
|---|---|---|
| 平台 | 小红书、知乎、公众号、B站、视频号 | 抖音、快手（后续扩展） |
| 内容形态 | 图文笔记、长文教程、专栏 | 短视频、直播（后续扩展） |
| 账号规模 | 10个以内 | 10个以上 |
| 部署方式 | 本地Windows | 云服务器（后续扩展） |
| 成本 | 全部免费开源工具 | 付费API、付费SaaS（后续扩展） |
| 团队 | 1人 | 多人协作 |

### 1.3 核心约束条件

- **零现金成本**：所有工具、模型、API必须免费，硬件使用现有设备
- **免费API优先**：LLM使用免费API（DeepSeek/通义千问/硅基流动/豆包等），多Key轮询避免额度限制
- **全自动化采集**：所有平台数据采集通过浏览器自动化脚本实现，不手动导出
- **可复现**：每个步骤有明确的操作文档，换一台机器能重新跑通
- **可回退**：任何自动化环节出问题，能立即切回手动操作

## 四、各模块详细实现方式

### 模块M1：账号管理与环境隔离

#### M1.1 多账号Cookie管理

**工具**：social-auto-upload 内置的多账号配置

**实现方式**：

1. 每个平台每个账号首次登录时，用Playwright打开对应平台的创作者中心，手动扫码登录
2. 登录成功后，Playwright将Cookie持久化到本地目录：`./cookies/{平台}/{账号名}.json`
3. 后续发布时，自动加载对应账号的Cookie，无需重复登录
4. Cookie过期时（通常7-30天），脚本检测到登录态失效，自动提醒重新扫码

**目录结构示例**：
```
./cookies/
├── xiaohongshu/
│   ├── ai_xiaobai.json
│   ├── ai_gongjukong.json
│   └── coder_toolbox.json
├── zhihu/
│   ├── ai_gongjupai.json
│   ├── kaiyuan_wajueji.json
│   └── ai_xiaolv_gongfang.json
├── bilibili/
├── wechat_mp/
└── wechat_channels/
```

#### M1.2 设备指纹与IP隔离

**实现方式**：

1. **浏览器Profile隔离**：在social-auto-upload的配置中，为每个账号指定独立的`user_data_dir`：
   ```yaml
   accounts:
     - platform: xiaohongshu
       name: ai_xiaobai
       user_data_dir: ./profiles/xhs/ai_xiaobai
       cookie_path: ./cookies/xiaohongshu/ai_xiaobai.json
   ```

2. **IP隔离（Clash方案）**：
   - 每个账号在Clash中绑定一个独立的代理节点（不同地区/不同线路）
   - 发布脚本在启动浏览器前，通过Clash外部控制器API自动切换到对应账号的节点：
     ```python
     import requests
     def switch_clash_proxy(node_name):
         # Clash外部控制器默认端口9090，需在config.yaml中开启external-controller
         url = "http://127.0.0.1:9090/proxies/Proxy"
         data = {"name": node_name}
         requests.put(url, json=data)
     ```
   - Clash配置文件中设置`external-controller: 127.0.0.1:9090`，并确保有足够的可用节点（10个号建议准备15+个节点备用）
   - 同平台账号必须使用不同节点，不同平台可复用节点
   - 节点可用性定期检测，失效节点自动切换到备用节点

3. **User-Agent随机化**：Playwright启动时随机选择UA，避免所有账号指纹完全一致

#### M1.3 发布节奏控制

**排期规则**：

| 规则 | 具体值 | 原因 |
|---|---|---|
| 每个账号每日发布上限 | 1篇 | 避免被判定为营销号批量发布 |
| 同平台账号发布间隔 | ≥2小时 | 降低同IP/同设备关联风险 |

### 模块M2：内容生产流水线

#### M2.1 爆款选题采集

**工具**：Spider_XHS（小红书）+ 自定义浏览器自动化脚本（知乎/B站）

**实现方式**：

1. **关键词批量搜索**：
   - 预设关键词库：`["codex 安装", "codex 使用教程", "minimax 部署", "AI工具推荐", "开源AI项目", "AI代码助手", "本地部署AI", "AI效率工具"]`
   - 用Spider_XHS按关键词搜索小红书笔记，抓取：标题、正文、点赞数、收藏数、评论数、发布时间、作者粉丝数
   - 筛选条件：点赞>50 OR 收藏>30，发布时间在30天内
   - 结果存入本地SQLite：`./data/raw_notes.db`

2. **知乎/B站自动化采集**：
   - 用Playwright编写脚本，自动打开知乎搜索页面，输入关键词，按"最多赞同"排序，抓取Top20问题的标题、赞同数、回答数、链接
   - 同理抓取B站搜索结果，按"最多播放"排序，抓取Top20视频的标题、播放量、UP主、链接
   - 采集结果存入同一个选题库，标注来源平台
   - 采集频率：每周1次，更新选题池

3. **选题评分排序**：
   - 对采集到的选题计算热度分：`热度分 = 点赞×0.3 + 收藏×0.4 + 评论×0.3`，按时间衰减（越新权重越高）
   - 取Top20作为本周候选选题池

**操作命令示例**：
```bash
# 启动Spider_XHS采集
cd ./tools/Spider_XHS
python main.py --keyword "codex 安装" --max_pages 5 --output ./data/raw_notes.db
```

#### M2.2 AI内容改写（免费LLM API）

**工具**：免费LLM API（DeepSeek / 通义千问 / 硅基流动 / 豆包），多Key轮询

**可用免费API清单**：

| API服务商 | 免费模型 | 免费额度 | 调用方式 | 注册地址 |
|---|---|---|---|---|
| **DeepSeek** | deepseek-chat | 新用户送额度，后续有免费调用额度 | OpenAI兼容 | platform.deepseek.com |
| **通义千问** | qwen-turbo / qwen-plus | 新用户免费额度，qwen-turbo长期免费 | OpenAI兼容 | dashscope.aliyun.com |
| **硅基流动** | Qwen2.5-7B/14B、DeepSeek等 | 新用户送额度，部分模型永久免费 | OpenAI兼容 | cloud.siliconflow.cn |
| **豆包API** | doubao-pro / doubao-lite | 新用户免费额度 | OpenAI兼容 | console.volcengine.com |
| **智谱GLM** | glm-4-flash | 长期免费 | OpenAI兼容 | open.bigmodel.cn |

> 以上平台均提供OpenAI兼容的API接口，可用统一的`openai` Python库调用，只需切换`base_url`和`api_key`。

**配置方式**：

1. 在各平台注册账号，获取API Key
2. 将所有Key存入配置文件`./config/api_keys.yaml`：
   ```yaml
   providers:
     - name: deepseek
       base_url: https://api.deepseek.com/v1
       api_key: sk-xxx
       model: deepseek-chat
       priority: 1
     - name: tongyi
       base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
       api_key: sk-xxx
       model: qwen-turbo
       priority: 2
     - name: siliconflow
       base_url: https://api.siliconflow.cn/v1
       api_key: sk-xxx
       model: Qwen/Qwen2.5-7B-Instruct
       priority: 3
     - name: doubao
       base_url: https://ark.cn-beijing.volces.com/api/v3
       api_key: sk-xxx
       model: doubao-lite-4k
       priority: 4
   ```

3. 多Key轮询策略：
   - 按priority顺序调用，第一个Key额度用尽或报错时自动切换到下一个
   - 记录每个Key的调用次数和剩余额度（如API支持查询）
   - 所有Key都不可用时，暂停任务并推送提醒

**调用代码示例**：
```python
from openai import OpenAI
import yaml

def load_providers(config_path="./config/api_keys.yaml"):
    with open(config_path, "r", encoding="utf-8") as f:
        return yaml.safe_load(f)["providers"]

def ai_chat(prompt, providers):
    """多Key轮询调用LLM API"""
    for p in providers:
        try:
            client = OpenAI(api_key=p["api_key"], base_url=p["base_url"])
            response = client.chat.completions.create(
                model=p["model"],
                messages=[{"role": "user", "content": prompt}],
                temperature=0.7,
                max_tokens=4000
            )
            return response.choices[0].message.content
        except Exception as e:
            print(f"[WARN] {p['name']}调用失败: {e}，切换下一个")
            continue
    raise RuntimeError("所有API Key均不可用")

# 使用
providers = load_providers()
result = ai_chat("请改写以下内容...", providers)
```

**改写流程**：

1. **输入**：采集到的爆款笔记原文 + 目标平台 + 目标账号定位
2. **Prompt模板**（按平台差异化，同v1.0，此处省略重复内容）
3. **批量改写脚本**：从选题库读取Top20，调用`ai_chat()`函数批量生成各平台版本，存入`./data/drafted/`目录
4. **改写质量检查**：
   - 自动检查字数是否符合平台要求
   - 自动检查是否包含必要的结构元素（标题、正文、标签）
   - 用LLM做一次"原创性自检"：让模型判断改写稿与原文的相似度，**>40%则重新改写**（v1.2从60%收紧到40%，参考行业标准：矩阵号内容相似度必须<40%，换视角重写而非同义词替换）
   - **结尾必须包含互动引导**（v1.2新增）：如"你在安装中遇到了什么问题？评论区告诉我～"或"需要完整配置文件的评论区扣1"，为未来私域引流和变现预留入口

> **⚠️ v1.2重要提醒：AI直发必被限流。** 参考成熟运营经验，AI生成的内容直接发布大概率会被平台判定为低质内容而限流。必须经过人工审核环节：①重写开头前50字（加入个人经历/真实细节/情绪钩子）；②验证所有代码命令和参数的准确性；③调整语气使其更像真人分享。人工审核是不可省略的强制环节，不是可选项。

#### M3.3 发布执行与状态监控

**执行流程**：

1. social-auto-upload启动后，按排期表轮询
2. 到达发布时间时：
   a. 加载对应账号的Cookie和浏览器Profile
   b. 打开对应平台的创作者中心发布页面
   c. 自动填写标题、正文、标签
   d. 上传图片（按顺序）
   e. 设置发布时间（立即或定时）
   f. 点击发布按钮
   g. 截图保存发布成功页面
3. 发布结果记录到`./data/publish_log.db`：
   - 内容ID、平台、账号、发布时间、状态（成功/失败）、失败原因、发布后链接、截图路径

**状态监控**：
- 每篇发布后立即检查是否成功（页面是否跳转到"发布成功"）
- 发布后10分钟、1小时、24小时分别回访，检查内容是否被下架/限流
- 失败自动重试（最多3次，间隔5分钟），超过3次标记为"需人工处理"

#### M3.4 失败重试机制

| 失败类型 | 自动处理 | 人工介入条件 |
|---|---|---|
| Cookie过期 | 暂停该账号所有发布，推送提醒 | 需要重新扫码登录 |
| 页面加载超时 | 刷新页面重试（最多3次） | 3次仍失败 |
| 图片上传失败 | 重新上传（最多3次） | 3次仍失败 |
| 内容含敏感词被拦截 | 记录敏感词，跳过发布 | 需要修改内容后重新提交 |
| 账号被限制发布 | 暂停该账号7天 | 需要检查账号状态 |
| 网络中断 | 等待网络恢复后继续 | 网络中断超过30分钟 |

#### M3.5 发布前合规红线检查（v1.2新增）

**⚠️ 以下红线必须在发布前自动检查，违反则拦截发布并提示人工修改。**

| 红线类型 | 具体规则 | 检查方式 | 违反处理 |
|---|---|---|---|
| **导流词** | 禁止出现"微信/VX/加我/扣扣/QQ/私信我"及谐音变体（如v信、薇信、+我） | 关键词匹配+谐音检测 | 拦截发布，提示修改 |

| **敏感词** | 政治敏感、色情低俗、暴力恐怖等平台违禁词 | 敏感词库匹配（可集成零克查词或自建词库） | 拦截发布 |

| **AI内容标注** | AI生成内容建议主动标注（平台政策趋势） | 人工确认 | 提示是否添加标注 |

**合规检查脚本实现**：在内容包进入发布队列前，运行`scripts/check_compliance.py`脚本，自动扫描标题和正文，命中红线则拦截并生成修改建议。

   - 输入：同一主题在不同平台的表现对比
   - Prompt：`请对比同一主题在小红书、知乎、B站的表现差异，分析各平台用户偏好，给出内容差异化策略。数据：{json_data}`

**复盘报告自动生成**：
- 每周一凌晨自动运行复盘脚本
- 生成Markdown格式报告：`./data/reports/复盘_YYYYWW.md`
- 包含：数据概览、Top/Bottom内容、原因分析、下周行动计划

#### M4.4 选题反馈闭环

复盘结果直接反馈到选题采集模块：
- 表现好的选题方向 → 增加关键词权重，采集更多同类内容
- 表现差的选题方向 → 降低权重或暂停采集
- 新发现的热门关键词 → 加入关键词库

### 模块M5：互动管理（轻量版）

MVP阶段不做全自动互动（风险高），只做**监控提醒+半自动回复**：

1. **评论监控**：
   - 每日采集各账号的最新评论（通过浏览器自动化抓取创作者中心的评论通知）
   - 用免费LLM API对评论做分类：`咨询类`（需要回复）、`赞美类`（可简单回复）、`负面类`（需人工处理）、`垃圾广告`（忽略）
   - 咨询类评论自动生成回复草稿，人工确认后发送

2. **私信提醒**：
   - 有新私信时，桌面推送通知（不自动回复，避免风险）
   - 私信内容摘要由免费LLM API生成，快速判断是否需要处理

3. **实现方式**：
   - 评论采集：扩展social-auto-upload的浏览器自动化能力，增加"读取评论通知"功能
   - 分类与回复草稿：调用免费LLM API（复用M2.2的多Key轮询机制）
   - 提醒：Windows Toast通知（Python的`win10toast`库）

### 10.2 后续优化方向

1. **视频内容扩展**：图文验证成功后，扩展到短视频（B站/抖音/视频号），可用AI生成口播文案+数字人/图文成片工具
2. **云服务器部署**：本地验证稳定后，迁移到云服务器实现24小时无人值守
3. **多模态内容生成**：集成AI图片生成（本地SD）和AI视频生成，减少手动截图工作量
4. **A/B测试系统**：对同一主题生成多个标题/封面版本，A/B测试后选择最优版本发布
5. **变现路径探索**：粉丝量达到一定规模后，探索引流私域、带货、广告、知识付费等变现方式
6. **团队协作扩展**：如验证成功且需要扩大规模，引入多人协作流程和审核机制
